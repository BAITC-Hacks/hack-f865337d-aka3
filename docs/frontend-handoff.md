# Передача frontend Career Quest

## Запуск на Windows

Из корня репозитория в PowerShell VS Code:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000. Node/npm для запуска и отдельная сборка не нужны: frontend/index.html, app.js, api.js, styles.css обслуживает FastAPI. Никаких внешних шрифтов, CDN, моков или AI-зависимостей. Актуальный Chrome/Edge поддерживает используемые ES-модули, AbortSignal.timeout/any, crypto.randomUUID; для удалённого размещения нужен HTTPS (локальный localhost/127.0.0.1 считается безопасным контекстом).

По умолчанию используется data/demo.sqlite3. Для новой демонстрации сохраните старую базу и задайте новый путь перед запуском:

```powershell
$env:CAREER_QUEST_DB = 'data/demo-new-session.sqlite3'
.\.venv\Scripts\python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Кнопка «Открыть демопрофиль» использует публичный учебный ключ DEMO_001. HR-ключ введите вручную в «Подключение и доступ»: учебный demo-hr, затем «Подключиться» и «HR». Токены не сохраняются в local/sessionStorage. После перезагрузки нужно снова подключиться; данные остаются в SQLite. При реальных данных задайте CAREER_QUEST_NORMALIZED_DATA и собственные серверные CAREER_QUEST_TOKENS. Импорт не выдаёт права новым сотрудникам автоматически.

Адрес backend задаётся полем подключения; пусто — тот же origin. При отдельном frontend-сервере настройте CAREER_QUEST_CORS_ORIGINS; localhost и 127.0.0.1 — разные origin. По умолчанию разрешены оба варианта для портов 5173/3000.

## Что сделано

- Экран сотрудника: роль/грейд, цель с источником, сохранение выбора, серверный процент покрытия, таблица навыков и критических разрывов, до трёх рекомендаций с независимыми прогнозами и источником объяснения, история и завершение начатых участий.
- Демовыполнение с блокировкой двойного нажатия. Неопределённые запросы сохраняют ключ и тело в sessionStorage по backend/сотруднику и доступны для повтора после обновления вкладки. Новое повторяемое участие получает новый participation_id. После любого успешного POST запрашиваются свежие GET, сохранённый ответ не используется как актуальный снимок.
- Отдельное сообщение, если выполнение/цель/импорт сохранились, но обновить интерфейс не удалось. Ошибки сервера не подменяются моками. Профиль остаётся виден, если не загрузились рекомендации.
- HR: частые дефициты, отсутствие следующего шага с причиной, участие; обновление при открытии вкладки и после импорта. Защита сервером.
- Импорт одного UTF-8 JSON-файла с новыми профилями и их историей. Файл выбирается стандартным контролом, результат содержит кнопки открытия профилей. Пример доступен в интерфейсе. Формат описан в API-контракте; Excel/CSV и стартовый кит не обещаются.
- Панель AI честно показывает отсутствие подключения; предусмотрены ввод, история, отправка, ожидание, ошибки, быстрые вопросы и event_id. Внешнюю модель не подключали.

## Изменения backend для первого участника

| Файл | Изменение |
|---|---|
| backend/models.py | Добавочные поля Profile/Recommendation; HistoryItem, ImportRequest, GoalRequest |
| backend/engine.py | История до as_of, справочник целей, причина блокировки по дате оценки; format/repeatable в рекомендациях; формулы и ранжирование сохранены |
| backend/storage.py | Атомарные append-only импорт и сохранение цели; будущие completed не вызывают already_completed; явный ID будущего участия отклоняется |
| backend/main.py | GET /hr/overview, POST /imports, POST /employees/{id}/goal; актуальная SQLite в проверке существования и health; статика; CORS для 127.0.0.1; версия 1.2 |
| scripts/export_examples.py | Явный UTF-8 при экспорте на Windows |
| docs/openapi.json, docs/examples/*.demo.json | Повторно экспортированы реальные контракты и ответы |

Правило даты оценки сохранено: completed начисляются строго после last_review_date; при равенстве даты оценки и симуляции выполнение блокируется, причина и disabled-кнопка теперь видны. Это исключает повторный учёт исторических уровней. Рекомендации при этом остаются прогнозом будущего развития. Изменение правила требует согласования границы оценки, простая замена сравнения небезопасна.

## AI: следующий участник

Уже реализованный контракт генерации объяснений описан в ai-contract.md как внутренний интерфейс; вызова модели пока нет. Он должен получать актуальный Store.snapshot(), сохранять fallback при ошибках и не менять числа/доступность.

**Предложенный HTTP-контракт чата — ещё НЕ реализованный маршрут:**

`POST /employees/{employee_id}/chat`, обычный Bearer и existing authorized_data; сотрудник только себе, HR любому профилю.

```json
{
  "message": "Почему этот шаг?",
  "event_id": "DEMO_DESIGN",
  "history": [{"role": "user", "content": "Что дальше?"}]
}
```

event_id допускает null; history содержит только user/assistant (последние 20 сообщений); message — 1–2000 символов. Ответ `{ "message": "Текст ответа" }`. Валидация event_id и размеров, авторизация, системный промпт, таймаут модели и секреты — на backend. Ошибки в существующем формате detail; 503 при недоступности модели, 404/501 при неподключённом маршруте.

Клиентский метод уже есть в frontend/api.js. После реализации и проверки маршрута включить CHAT_ENABLED в frontend/app.js. При смене профиля клиент отменяет запрос, очищает диалог и проверяет generation до вставки ответа. Внешние ключи никогда не передавать в браузер. Профиль/рекомендации/выполнение не зависят от чата.

## Соответствие требованиям и ограничения

Оригинальное ТЗ и файлы организаторов в текущей рабочей копии не найдены; запрошено их расположение. Нельзя заявить закрытие его критериев или баллы. По тексту пользовательского задания реализованы сотрудник, реальное выполнение/сохранение, HR с авторизацией, выбор цели, импорт внутреннего формата и подготовка AI-панели. Частично: проверка frontend ограничена тестами без настоящего браузера; импорт совместим только с текущей схемой проекта. Заблокировано отсутствием исходных документов: адаптер организаторов и проверка соответствия оригинальному ТЗ. Внешний AI и финальная сдача остаются третьему участнику.

В API нет длительности и человекочитаемого справочника навыков; UI показывает доступный формат/дату и идентификаторы навыков, не выдумывает данные. Статические токены — механизм хакатона, не полноценная система входа. Импорт не перезаписывает существующих людей и не создаёт токены. Дата симуляции фиксирована; переход к другой дате с будущими записями истории требует отдельного сценария, который этот этап не вводит.

## Короткое демо (свежая база)

1. Открыть `/`, нажать «Открыть демопрофиль»: Алия [ДЕМО], цель Senior, покрытие 60%, SYSTEM_DESIGN=2.
2. Найти DEMO_DESIGN, объяснить источник «Правила сервера (без AI)» и независимый прогноз; нажать «Выполнить — демо»: покрытие 70%, навык 3, запись в истории.
3. Перезагрузить страницу, снова открыть демопрофиль: результат сохранён. Проверить панель «AI-чат пока не подключён».
4. Ввести demo-hr, подключиться, открыть HR. Скачать пример JSON и импортировать его один раз; увидеть 4 сотрудников, открыть IMPORTED_001 с историей. Повторный файл отклоняется без дублирования.
5. Через HR открыть DEMO_003: цели нет и процент не выдуман. Выбрать Senior, сохранить, перезагрузить и проверить. У DEMO_002 доступно завершение начатого DEMO_H04 в истории.
6. Проверить неверный токен (401), ключ сотрудника на HR (403), некорректный JSON и недоступный backend. Оценить читаемость интерфейса на экране ноутбука.
