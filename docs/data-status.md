# Данные и допущения

По явному запросу пользователя backend теперь запускается на синтетическом наборе demo/dataset.json. Все имена помечены [ДЕМО], ID начинаются с DEMO_. Это НЕ данные организаторов. Исходный PDF прочитан; README стартового кита и реальные JSON/CSV недоступны.

Подтверждено PDF: уровни 0–5, gain/max_level, до трёх рекомендаций, многофакторные объяснения, прогресс и разграничение прав.

Допущения, которые нужно сверить при подключении стартового кита:
- Нормализованная структура Dataset в backend/models.py — наша схема. Загрузка отделена в backend/loader.py; адаптер организаторов ещё предстоит написать.
- Симуляция фиксирована на 2026-10-01, последняя оценка задаёт исходные уровни.
- Учитываются только completed строго после оценки и не позже даты симуляции. Остальные статусы прирост не дают.
- new_level = max(current, min(current + gain, max_level)); отсутствующий навык равен 0.
- История содержит одну запись на participation_id. Порядок — дата, при равных датах порядок в массиве; новые выполнения добавляются в конец. Это уточнение прежнего предварительного порядка по ID обеспечивает воспроизводимость нескольких выполнений за один день.
- Обязательные активности не рекомендуются и не завершаются этим добровольным демо endpoint.
- Пустые roles/grades означают отсутствие ограничения. prerequisites проверяются по актуальным уровням.
- Сессии считаются уже доступными для записи; вместимость/таймзона/дедлайн неизвестны. self_paced не требует сессии; остальные требуют дату >= даты симуляции.
- Кнопка выполнения — именно деморежим: даже будущую доступную сессию можно завершить немедленно датой симуляции. Это не подтверждение реального посещения.
- Если дата оценки совпадает с датой выполнения, POST возвращает 409 вместо незаметного отсутствия прироста.
- Повторяемость задаётся repeatable, без захардкоженного EV_036. Каждое новое участие требует нового participation_id; сетевой retry сохраняет прежние ID и Idempotency-Key.
- При отсутствии цели предлагается следующий существующий грейд той же роли. Нет следующего грейда — требуется выбор цели.
- Прогресс и веса критических навыков/истории — наша объяснимая эвристика, не правило ТЗ.

SQLite хранит валидированный снимок и ответы идемпотентных запросов. seed не перезаписывает накопленный прогресс. Изменение исходного набора требует нового файла БД через CAREER_QUEST_DB; существующие данные автоматически не удаляются.

Этап frontend: импорт внутренней схемы (только новые профили с историей), HR-агрегации и сохранение цели реализованы. Оригинальный PDF и стартовый кит в текущей рабочей копии недоступны; утверждение о ранее прочитанном PDF выше относится к предыдущему этапу и не является проверкой на этапе frontend. Адаптер данных организаторов, чат и внешняя модель остаются следующим этапом.
